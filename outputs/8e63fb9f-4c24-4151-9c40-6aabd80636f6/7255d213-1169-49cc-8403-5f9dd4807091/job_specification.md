## 4. Evidence & Evaluation Rules

### Understanding of cloud platforms (AWS / Azure / GCP)
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Cloud platforms provide scalable infrastructure for AI workloads via managed services like EC2, S3, and databases.
> - **Strong Candidate Signals:** Deployed production ML models using AWS SageMaker or Azure ML; Managed cloud cost optimization for AI pipelines
> - **Weak / Ambiguous Signals:** Mentioned cloud without specific services; Used generic terms like 'cloud infrastructure' without metrics
> - **Screening Question:** Have you deployed an AI model in production using AWS, Azure, or GCP?

### Knowledge of deployment, Docker, and basic DevOps practices
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Docker containers package applications with dependencies for consistent deployment across environments.
> - **Strong Candidate Signals:** Built and deployed Docker images for AI models in CI/CD pipelines; Configured Jenkins or GitHub Actions for automated testing
> - **Weak / Ambiguous Signals:** Described Docker concepts without hands-on deployment; Used Docker in academic projects without production context
> - **Screening Question:** Can you share an example of deploying an AI model using Docker in production?

### Ability to quickly prototype AI-driven products
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI prototyping involves rapidly building and testing models to validate business value before full-scale deployment.
> - **Strong Candidate Signals:** Built a working AI prototype with 80%+ accuracy in <7 days; Validated prototype against real user data for business impact
> - **Weak / Ambiguous Signals:** Used pre-trained models without customization; Prototype lacked metrics or user validation
> - **Screening Question:** Walk me through a recent AI prototype that solved a specific business problem.

### What We Look For
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI Native Engineers design systems from scratch using AI/ML principles to solve real-world problems directly.
> - **Strong Candidate Signals:** Built production ML models with end-to-end ownership; Deployed AI solutions using TensorFlow/PyTorch in production
> - **Weak / Ambiguous Signals:** Learned AI concepts through tutorials; Contributed to academic AI projects without deployment
> - **Screening Question:** Have you designed and deployed an AI system that handles real user data at scale?

### Strong problem-solving mindset
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Strong problem-solving means breaking complex issues into manageable parts with systematic, iterative approaches.
> - **Strong Candidate Signals:** Solved production bugs through root-cause analysis; Optimized system performance by 40%+ via data-driven experiments
> - **Weak / Ambiguous Signals:** Solved simple coding challenges on platforms like LeetCode; Identified issues without implementing fixes
> - **Screening Question:** Walk me through how you fixed a production issue that impacted users.

### Ability to work in fast-paced startup environment
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Startup agility requires rapid iteration, cross-functional collaboration, and adapting to changing priorities without slowing delivery.
> - **Strong Candidate Signals:** Delivered features in 2-week sprints with customer feedback; Managed technical debt during product pivots
> - **Weak / Ambiguous Signals:** Worked in a team without clear ownership of outcomes; Adapted to changes without impacting delivery timelines
> - **Screening Question:** How did you handle a situation where your tech stack needed rapid changes?

### Passion for AI-first product building
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Building products that prioritize AI capabilities from inception rather than adding them later.
> - **Strong Candidate Signals:** AI product prototypes with real user impact metrics; Direct involvement in AI feature design decisions; Published AI system architecture diagrams
> - **Weak / Ambiguous Signals:** Passive mentions of 'AI interest' without projects; Tutorial-level AI experiments without production context
> - **Screening Question:** Describe an AI feature you built where you owned the end-to-end lifecycle from data to deployment.

### Ownership-driven and self-motivated attitude
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Proactively driving work without external direction while maintaining accountability.
> - **Strong Candidate Signals:** Completed projects with measurable outcomes; Ownership of technical debt reduction initiatives; Cross-functional dependency management
> - **Weak / Ambiguous Signals:** Self-reported motivation without concrete examples; Task completion without ownership context
> - **Screening Question:** Give an example where you solved a problem without waiting for permission.
