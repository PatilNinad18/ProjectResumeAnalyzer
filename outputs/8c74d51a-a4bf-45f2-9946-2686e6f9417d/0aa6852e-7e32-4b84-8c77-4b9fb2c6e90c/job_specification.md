## 4. Evidence & Evaluation Rules

### Understanding of cloud platforms (AWS / Azure / GCP)
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Cloud platforms provide scalable infrastructure for AI workloads through managed services and global network optimization.
> - **Strong Candidate Signals:** Deployed production ML models on AWS SageMaker or Azure ML; Managed cloud cost allocation for AI experiments via AWS Cost Explorer
> - **Weak / Ambiguous Signals:** Mentioned cloud platforms without deployment context; Tutorial-level cloud projects with no metrics
> - **Screening Question:** Have you deployed an AI model to production using AWS or Azure?

### Knowledge of deployment, Docker, and basic DevOps practices
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Docker containers package applications with dependencies for consistent deployment across environments.
> - **Strong Candidate Signals:** Containerized AI models with Dockerfiles and CI/CD pipelines; Production deployments using Kubernetes or similar orchestration
> - **Weak / Ambiguous Signals:** Basic Docker tutorials without production usage; Manual deployment without automation
> - **Screening Question:** Can you share a production example where Docker improved AI deployment?

### Ability to quickly prototype AI-driven products
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Rapid AI prototyping involves building and testing models with minimal code changes to validate ideas quickly.
> - **Strong Candidate Signals:** Built 3+ AI prototypes in <48 hours using frameworks like PyTorch; Validated prototypes with real user data before full deployment
> - **Weak / Ambiguous Signals:** Theoretical knowledge without hands-on prototyping; Prototypes that never reached production
> - **Screening Question:** Walk me through a recent AI prototype you built in under 24 hours.

### What We Look For
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI Native Engineers build systems from the ground up using AI/ML models as core components, not just add-ons.
> - **Strong Candidate Signals:** Built production ML pipelines with custom model training loops; Deployed inference services using TensorFlow Serving or PyTorch; Optimized model latency under 100ms for real-time applications
> - **Weak / Ambiguous Signals:** Used AI libraries without understanding model lifecycle; Implemented basic ML models in academic projects
> - **Screening Question:** Describe a time you designed an AI system from scratch, not just integrated existing models.

### Strong problem-solving mindset
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Strong problem-solving involves breaking complex technical challenges into actionable steps with measurable outcomes.
> - **Strong Candidate Signals:** Reduced system latency by 30% through algorithmic optimization; Solved production scaling issues during peak traffic spikes; Debugged distributed systems failures using logging and tracing
> - **Weak / Ambiguous Signals:** Solved simple coding puzzles without real-world impact; Identified issues but didn't implement fixes
> - **Screening Question:** Walk me through how you fixed a critical production bug in your last role.

### Ability to work in fast-paced startup environment
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Startup environments require rapid iteration, minimal viable product focus, and tolerance for technical debt.
> - **Strong Candidate Signals:** Launched MVP with 50% of features in 3 months; Adapted architecture mid-sprint to meet changing priorities; Balanced technical debt with feature delivery velocity
> - **Weak / Ambiguous Signals:** Worked in slow-paced teams without clear direction; Prioritized stability over speed during pivots
> - **Screening Question:** How did you handle a technical challenge when your startup had to pivot quickly?

### Passion for AI-first product building
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Building products where AI is the primary driver of value from inception.
> - **Strong Candidate Signals:** Built AI features that directly impact user metrics like engagement or conversion rates; Led end-to-end AI product development cycles with clear business outcomes
> - **Weak / Ambiguous Signals:** Mentioned AI without concrete examples or metrics; Described AI concepts but not applied to real products
> - **Screening Question:** Can you share an example where your AI work directly improved a business metric?

### Ownership-driven and self-motivated attitude
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Proactively taking initiative and owning outcomes without external supervision.
> - **Strong Candidate Signals:** Delivered projects with clear ownership and measurable results; Initiated solutions to technical debt or process improvements independently
> - **Weak / Ambiguous Signals:** Claimed ownership without specific deliverables; Described tasks but not outcomes or accountability
> - **Screening Question:** Tell me about a time you took initiative to solve a problem without being asked.
