## 4. Evidence & Evaluation Rules

### Understanding of cloud platforms (AWS / Azure / GCP)
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Cloud platforms provide scalable infrastructure for AI workloads via IaaS/PaaS services like VMs, databases, and managed ML services.
> - **Strong Candidate Signals:** Deployed production ML models using AWS SageMaker or Azure ML; Managed cloud cost optimization for AI pipelines (e.g., spot instances)
> - **Weak / Ambiguous Signals:** Mentioned cloud platforms without specific services or metrics
> - **Screening Question:** Have you deployed an AI model on AWS/Azure/GCP with measurable cost savings?

### Knowledge of deployment, Docker, and basic DevOps practices
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Docker containers package applications with dependencies for consistent deployment across environments.
> - **Strong Candidate Signals:** Containerized AI models using Docker Hub with CI/CD pipelines; Deployed production services via Kubernetes or similar orchestration
> - **Weak / Ambiguous Signals:** Basic Docker commands without production deployments
> - **Screening Question:** Can you show a Dockerfile for an AI model with CI/CD integration?

### Ability to quickly prototype AI-driven products
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI prototyping involves rapidly building and testing MVPs using frameworks like TensorFlow or PyTorch.
> - **Strong Candidate Signals:** Built AI prototypes with 30-day delivery cycles using MLOps tools; Iterated on model performance metrics (e.g., accuracy, latency) in production
> - **Weak / Ambiguous Signals:** Tutorial projects without real-world data or ownership
> - **Screening Question:** Describe an AI prototype you shipped with clear metrics and impact.

### What We Look For
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI Native Engineers design systems from scratch using AI/ML principles for real-world applications.
> - **Strong Candidate Signals:** Built production ML models with end-to-end deployment in cloud environments; Contributed to AI feature pipelines with measurable business impact
> - **Weak / Ambiguous Signals:** Mentioned AI concepts without implementation examples; Tutorial projects with no production metrics
> - **Screening Question:** Describe a time you designed an AI system from scratch that handled real user data.

### Strong problem-solving mindset
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Strong problem-solving involves breaking complex issues into testable components with iterative validation.
> - **Strong Candidate Signals:** Solved production-scale bugs through root cause analysis and data-driven fixes; Optimized system performance by 20%+ through targeted experiments
> - **Weak / Ambiguous Signals:** Generic statements about 'problem-solving' without examples; Theoretical problem-solving without real-world application
> - **Screening Question:** Walk me through how you debugged a complex production issue last month.

### Ability to work in fast-paced startup environment
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Startup environments demand rapid iteration, clear communication, and adaptability to changing priorities.
> - **Strong Candidate Signals:** Ship features in 2-week sprints with measurable user engagement metrics; Managed cross-functional teams during product pivots without delays
> - **Weak / Ambiguous Signals:** Experience in 'fast-paced' environments without specific examples; Long-term project management in stable environments
> - **Screening Question:** How did you adjust your workflow when a critical business priority changed?

### Passion for AI-first product building
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI-first product building means designing systems where AI solutions drive core user value from day one, not as an afterthought.
> - **Strong Candidate Signals:** Built AI features that directly impact user metrics like retention or conversion rates; Led end-to-end AI feature development from data collection to production deployment
> - **Weak / Ambiguous Signals:** Mentioned AI without specific product impact examples; Worked on AI projects as a junior contributor without ownership
> - **Screening Question:** Describe an AI feature you built where the model directly improved user outcomes, not just technical complexity.

### Ownership-driven and self-motivated attitude
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Ownership-driven engineers proactively solve problems and drive decisions without waiting for others to act.
> - **Strong Candidate Signals:** Initiated and resolved critical production issues without manager approval; Championed technical solutions that reduced team latency by 20%+ through self-ownership
> - **Weak / Ambiguous Signals:** Claimed ownership without concrete examples of impact; Described tasks as 'responsible for' without demonstrating autonomy
> - **Screening Question:** Tell me about a time you fixed a problem that others avoided addressing.
