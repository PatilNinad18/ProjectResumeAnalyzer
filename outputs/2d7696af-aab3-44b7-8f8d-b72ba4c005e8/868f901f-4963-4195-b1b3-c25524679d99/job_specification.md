## 4. Evidence & Evaluation Rules

### Understanding of cloud platforms (AWS / Azure / GCP)
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Cloud platforms provide scalable infrastructure for AI workloads via managed services like EC2, S3, and databases.
> - **Strong Candidate Signals:** Deployed production ML models on AWS SageMaker or Azure ML; Managed cloud cost optimization for AI pipelines using AWS Cost Explorer
> - **Weak / Ambiguous Signals:** Mentioned cloud platforms without specific services or metrics; Used generic terms like 'cloud' in project descriptions without context
> - **Screening Question:** Have you deployed an AI model on AWS, Azure, or GCP with production metrics?

### Knowledge of deployment, Docker, and basic DevOps practices
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Docker containers package applications for consistent deployment across environments while DevOps practices automate CI/CD pipelines.
> - **Strong Candidate Signals:** Containerized AI models using Docker with CI/CD integration; Implemented infrastructure-as-code for model deployments via Terraform
> - **Weak / Ambiguous Signals:** Docker tutorials without production deployment experience; Basic DevOps knowledge without pipeline automation
> - **Screening Question:** Can you describe a Dockerized AI deployment with CI/CD?

### Ability to quickly prototype AI-driven products
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Rapid AI prototyping involves creating functional models quickly using frameworks like PyTorch or TensorFlow to validate ideas.
> - **Strong Candidate Signals:** Built a production-ready prototype with 70%+ accuracy in <2 weeks; Used MLOps tools like MLflow for tracking prototypes
> - **Weak / Ambiguous Signals:** Prototype projects without clear metrics or timelines; Mentioned 'AI prototyping' without technical specifics
> - **Screening Question:** Give an example of a prototype you built that met business goals?

### What We Look For
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** The ability to design and implement AI models from scratch with production-ready deployment.
> - **Strong Candidate Signals:** Built ML pipelines using PyTorch/TensorFlow for real-world applications; Deployed models via Kubernetes or serverless platforms with monitoring
> - **Weak / Ambiguous Signals:** Mentioned AI frameworks without implementation context; Tutorial projects with no production metrics
> - **Screening Question:** Describe a time you built an AI model that handled production traffic under 100ms latency.

### Strong problem-solving mindset
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** The capacity to break down complex problems into solvable steps and iterate efficiently.
> - **Strong Candidate Signals:** Solved production-scale issues with quantifiable impact; Used structured debugging techniques for distributed systems
> - **Weak / Ambiguous Signals:** Vague statements like 'good at solving problems'; Academic problem sets without real-world constraints
> - **Screening Question:** Walk me through how you debugged a production issue that caused 50% latency spikes.

### Ability to work in fast-paced startup environment
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Adaptability to rapid iteration cycles and shifting priorities common in early-stage tech companies.
> - **Strong Candidate Signals:** Launched features within 2-week sprints with clear ownership; Reduced technical debt during product pivots
> - **Weak / Ambiguous Signals:** Generic claims of 'working well in fast-paced environments'; Long-term planning without adaptability evidence
> - **Screening Question:** How did you adjust your approach when a key feature requirement changed mid-sprint?

### Passion for AI-first product building
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** AI-first product building means prioritizing AI capabilities from early design stages to ensure intelligent features drive real user value.
> - **Strong Candidate Signals:** Built AI features in production without manual data pipelines; Reduced user task completion time by 20%+ via AI integration; Led AI feature rollout with clear metrics tied to business outcomes
> - **Weak / Ambiguous Signals:** Mentioned AI in a project without ownership or metrics; Used AI tools for academic exercises without production impact
> - **Screening Question:** Can you describe an AI feature you built that directly improved user outcomes?

### Ownership-driven and self-motivated attitude
> **[AI Guidance — Evaluator Aid]**
> - **Concept Summary:** Ownership-driven engineers proactively solve problems and drive decisions without waiting for others.
> - **Strong Candidate Signals:** Resolved critical production issues without escalation; Championed technical solutions across cross-functional teams; Delivered features with measurable impact within 2-week sprints
> - **Weak / Ambiguous Signals:** Volunteered for tasks without ownership of outcomes; Acknowledged others' work without taking responsibility
> - **Screening Question:** Tell me about a time you fixed a problem without waiting for someone else to act.
